# ADR 0003 — 청킹 전략 (Chunking Strategy)

- 상태(Status): Provisional (1차 결정, 13단계 평가 후 재검토)
- 날짜(Date): 2026-05-25
- 작성자(Author): vittroi384
- 관련 단계(Stage): Phase 1 / 3단계 (하이브리드 데이터소스 + 청킹/임베딩 ADR)
- 관련 ADR: ADR 0004 (임베딩 모델), ADR 0005 (하이브리드 데이터소스)

## 맥락 (Context)

Drive 기반 사내 RAG 챗봇은 GCS에 적재된 공용 문서(PDF, DOCX, TXT, MD 등)를
Vertex AI Search(현 Agent Search)로 인덱싱한다. RAG 품질은 문서를 어떤 단위로
잘라(chunk) 임베딩하느냐에 크게 좌우된다. 청크가 너무 크면 검색 정밀도가 떨어지고
LLM 컨텍스트에 노이즈가 섞이며, 너무 작으면 문맥이 끊겨 답변 근거가 부실해진다.

제약 및 환경:
- 문서는 한국어 중심(사내 정책/매뉴얼/FAQ/회의록).
- 1차 운영은 개인 GCP에서 가짜/샘플 문서로 동작 검증, 회사 실제 문서는 13~15단계
  회사 GCP 이전 후 적재(보안 정책 범위 내).
- Vertex AI Search는 자동 청킹을 제공하며, 콘솔에서 청크 단위가 직접 노출되지 않는다.
- 솔로 개발자, 주 7시간. 초기에 커스텀 청킹 파이프라인을 구축하면 비용 대비 효율이 낮다.

## 결정 (Decision)

1차 운영은 **Vertex AI Search의 자동 청킹**을 그대로 사용한다.
커스텀 청킹은 13단계 골든셋 평가 결과 한국어 의미 분할 품질이 부족할 경우에만 도입한다.

커스텀 청킹 도입 시 초기 파라미터(실험 대상):
- 청크 크기: 500~1000 토큰
- 오버랩: 100~200 토큰
- 분할 우선순위: 문단(paragraph) > 섹션(section) > 문장(sentence)

청크 메타데이터(검색 필터링/출처 표기용):
- `source_file` — 원본 파일명
- `source_uri` — GCS URI (출처 링크, 환각 방지 근거 표기)
- `chunk_index` — 문서 내 청크 순번
- `created_at` — 적재 시각
- `folder` — 논리 분류(company-policies, manuals, faq, meeting-notes)

## 근거 (Rationale)

- **단순함 우선**: 자동 청킹은 추가 코드/인프라가 없고, 초기 목표(검색 동작 검증)에 충분하다.
- **측정 후 최적화**: 청킹 품질은 정량 측정(13단계 골든셋) 없이 판단하기 어렵다.
  근거 없이 커스텀 파이프라인을 먼저 짜는 것은 조기 최적화다.
- **비용**: 커스텀 청킹은 별도 전처리 컴퓨팅/저장이 필요하다. 트래픽(7~10명)
  대비 자동 청킹이 경제적이다.

## 결과 (Consequences)

긍정적:
- 3단계에서 청킹 코드 0줄로 인덱싱/검색 파이프라인을 가동.
- 13단계 평가 결과가 "자동 청킹으로 충분"이면 커스텀 작업 자체가 불필요.

부정적/리스크:
- 자동 청킹의 한국어 의미 분할 품질을 사전에 보장할 수 없다(블랙박스).
- 청크 단위가 콘솔에 직접 노출되지 않아, 품질은 검색 결과 snippet과 골든셋 지표로
  간접 측정해야 한다(7단계 코드, 13단계 평가).

## 운영 메모 — 입력 포맷 제약 (3단계 실측, 2026-05-25)

Vertex AI Search(현 Agent Search)의 Cloud Storage 자동 청킹은 **markdown(.md)을
지원하지 않는다**. 색인 시 `content.mime_type "text/markdown" not allowed` 오류로
스킵된다(허용: pdf, docx, txt, html, xml 등).

→ 자동 청킹을 전제로 하더라도 **적재 전 포맷 정규화 전처리**가 필요하다.
   회사 실제 문서 적재(13~15단계) 전에 md → txt/html 변환 단계를 파이프라인에
   포함해야 한다. 3단계에서는 md 2개를 txt로 수동 변환해 우회했다.
   이 전처리 요구사항은 커스텀 청킹 도입 여부와 무관하게 항상 적용된다.

## 재검토 트리거 (Revisit Triggers)

- 13단계 골든셋에서 Recall@5 / MRR이 목표치 미달.
- 특정 문서 유형(긴 PDF, 표 중심 문서)에서 근거 청크가 반복적으로 누락.
- 회사 실제 문서 적재(13~15단계) 후 한국어 검색 품질 저하 관찰 시.

# ADR 0001 — 회사 = GCP 프로젝트 1:1 매핑

- 상태: Accepted
- 날짜: 2026-05

## 배경
사내 챗봇을 여러 회사에 제공하려면 데이터/비용/권한을 어떻게 분리할지 정해야 한다. 일반적인 SaaS는 단일 인프라에 여러 고객을 태우는 멀티테넌트 방식을 쓴다. 그러나 본 제품은 회사 문서라는 민감 데이터를 다루고, 운영자는 솔로 개발자다.

## 선택지
1. **단일 멀티테넌트**: 하나의 GCP 프로젝트에 company_id로 모든 회사 데이터 격리.
2. **회사당 독립 GCP 프로젝트**: 회사 = 프로젝트 1:1.

## 결정
**회사당 독립 GCP 프로젝트 (1:1 매핑)** 를 채택한다.

## 근거
- **데이터 격리**: 프로젝트 경계가 곧 격리 경계. 애플리케이션 버그로 인한 회사 간 데이터 누출이 구조적으로 불가능.
- **비용 추적**: 프로젝트 단위 청구 → 회사별 원가가 그대로 보임. 가격 책정 근거가 됨.
- **권한 격리**: IAM이 프로젝트 단위라 최소 권한 적용이 단순.
- **Terraform 모듈화 용이**: 신규 회사 = 모듈 `apply` 한 번(19단계). 멀티테넌트의 런타임 분기보다 검증이 쉬움.

## 트레이드오프
- 회사 수가 많아지면 프로젝트 관리 오버헤드 증가(수십~수백 단위에서 비효율). 단, 본 제품의 목표 고객 규모(소수 정예)에서는 비현실적 우려.
- 공통 코드 배포를 회사 수만큼 반복 → CI/CD 자동화(18단계)로 상쇄.
- 멀티테넌트 특유의 자원 공유 절감 효과 포기 → 대신 격리/추적/단순성 확보.

# ADR 0001 — 회사 = GCP 프로젝트 1:1 매핑

- 상태: Accepted
- 날짜: 2026-05

## 배경
사내 챗봇을 어느 GCP 프로젝트에 둘지, 데이터/비용/권한을 다른 워크로드와 어떻게 분리할지 정해야 한다. 일반적인 SaaS는 단일 인프라에 여러 고객을 태우는 멀티테넌트 방식을 쓴다. 그러나 본 프로젝트는 회사 문서라는 민감 데이터를 다루고, 운영자는 개발자 1명이다.

## 선택지
1. **단일 멀티테넌트**: 하나의 GCP 프로젝트에 company_id로 모든 회사 데이터 격리.
2. **회사당 독립 GCP 프로젝트**: 회사 = 프로젝트 1:1.

## 결정
**회사당 독립 GCP 프로젝트 (1:1 매핑)** 를 채택한다.

## 근거
- **데이터 격리**: 프로젝트 경계가 곧 격리 경계. 애플리케이션 버그로 인한 회사 간 데이터 누출이 구조적으로 불가능.
- **비용 추적**: 프로젝트 단위 청구 → 챗봇 원가가 다른 워크로드와 섞이지 않음.
- **권한 격리**: IAM이 프로젝트 단위라 최소 권한 적용이 단순.
- **Terraform 모듈화 용이**: 신규 배포 = 모듈 `apply` 한 번(계획). 멀티테넌트의 런타임 분기보다 검증이 쉬움.

## 트레이드오프
- 배포 대상이 늘어나면 프로젝트 관리 오버헤드 증가. 현재는 단일 배포라 해당 없음.
- 배포가 늘면 공통 코드 배포를 반복 → CI/CD 자동화(계획)로 상쇄.
- 멀티테넌트 특유의 자원 공유 절감 효과 포기 → 대신 격리/추적/단순성 확보.
